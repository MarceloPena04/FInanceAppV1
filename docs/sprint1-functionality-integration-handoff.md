## Read this first

This is the behavior contract for a future coding agent. **Behavior source:** `codex/sprint1-review-clarity-prompt` at `a9f19a5dd74766127e194d639e76bc479b6fb8f2`. **Visual starting point:** the Pennywise dashboard at `b8f228992d9184ab45f57067b94dcff8aa451672` (“First modifications/ minor adjustments done to the app”). The task is to put the source behavior into that earlier visual language; this document does not claim that integration has happened. `main` at `f5b41e2` already has the earlier fictional review demo, so the inventory below describes the **whole working source snapshot**, not merely the branch diff.

The product shows **detected activity from fictional notices**. “Detected net flow” means detected inflow minus detected outflow for the shown source and period. It is not a bank balance, money remaining, all spending, or a verified account history. A **source fact** is what a notice supplied; a **system interpretation** is the app's reading; a **user correction** is the person's later choice. Keep all three distinct. The working path uses browser `localStorage` in one profile; it has no live source, account service, or private multi-user storage. See `docs/product-contract.md`, `src/app/page.tsx`, and `docs/human-exercise.md`.

**Authority when documents disagree:** use the source commit's code and tests, then the latest explicit owner amendments in `docs/product-contract.md` and `docs/human-review-contract.md`. The older “provisional outflow” and “confirm unknown as generic expense” rules are superseded. `docs/fictional-scenario-manifest.md` has a stale final-review sentence saying a retained duplicate remains pending; the current `duplicateDecision` implementation confirms complete records when resolving Same or Separate. ## Button and control contract

| Screen control | What pressing or changing it must do | Important guard or scope |
| --- | --- | --- |
| Displayed in | Recalculate all-time/weekly figures, per-record effects, and conversion display in the chosen fictional reporting currency. | Never rewrite a source currency or an already locked default assumption. |
| Viewing source (hero and sticky copy) | Scope both summaries, review queue, activity, and ready confirmations to the chosen bank/account/card/assigned/unidentified source. | Does not claim complete bank coverage or a balance. |
| Week of | Select a UTC week for weekly net, inflow/outflow, explanation, and review-period breakdown. | All-time history still includes that week; ready confirmation remains across history. |
| What this covers; Review totals and coverage; How selected-week totals are calculated | Expand read-only explanation, pending split, or contribution trace. | Show source and period; never add This week to All-time history. |
| Review / Close | Open or collapse Needs review; inner Close returns focus to Review. | Banner/panel disappear at zero pending and return after Undo/new pending. |
| Select all ready; row checkboxes | Select ready rows only, with individual deselection possible. | Selection does not confirm anything. |
| Confirm selected; Confirm all ready | Confirm selected or all ready rows in the current source scope, including earlier weeks. | Recheck readiness; leave attention records pending; confirmation does not double-count known money. |
| Details; attention row; activity card | Open the same source-backed transaction detail dialog/sheet. | Keep source excerpts, assumptions, linked evidence, and action history inspectable. |
| Search; All/Income/Expense/Other | Filter the activity list; show a no-match message when empty. | Do not change figures or review work. |
| Save changes; Save and confirm; Confirm transaction | Save edited fields; optionally confirm when amount/currency/type and other required decisions are complete. | Save alone stays pending. Possible duplicate and unresolved conflicts block ordinary confirmation. |
| Confirm as neutral | Confirm a complete source transfer/withdrawal after explaining zero combined-flow impact. | If it was spending or income, the person must edit Type first. |
| Undo a field; Undo confirmation | Clear that override, or return a confirmed record to review. | Original notice facts and unrelated user choices remain. |
| Exclude / Restore | Suppress or restore one record's detected-flow effect. | Reversible; exclusion is not deletion. |
| Same transaction; Keep as separate; Undo duplicate decision | Decide whether a possible pair is one event or two; restore undecided state on Undo. | Same keeps both notices in linked evidence; never silently lose a later separate confirmation. |
| Close, Escape, backdrop | Close the detail view, asking before discarding unsaved edits. | Return focus to the row or a sensible Activity/review heading. |
| Replay focused fixtures; Process all fixtures; Reset demo | Reprocess the 16 focused notices, process the full fictional set, or confirm and restore the focused seed. | These are demo utilities, not live import/sync or server deletion. |

The detail view is a native modal on desktop and a bottom sheet at narrow widths. Preserve labelled controls, visible focus, keyboard access, `aria-expanded`/`aria-pressed` state, result announcements, error alerts, reduced-motion handling, and the compact sticky toolbar. These are present in `src/app/page.tsx`, `src/app/activity-controls.tsx`, and `src/app/globals.css`; the repository has domain/fixture tests, **not automated DOM or accessibility tests**.
